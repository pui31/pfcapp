# PFCApp — Product Overview CANON

## この文書の役割

PFCApp全体の目的、子ども向け／大人向けの2アプリの関係、共通基盤に関する正式なWHAT / WHYを定める。

個別アプリのUX・仕様は、それぞれのCANONを参照する。

- 子ども向け: `canon/kids-app.md`
- 大人向け: `canon/adult-app.md`

## プロダクト構成

PFCAppは、食事記録とPFC（たんぱく質・脂質・炭水化物）を扱うアプリ群である。

同じ食品・栄養データ基盤を共有できる構造を目指す一方、子ども向けと大人向けでは目的と体験を明確に分離する。

### 子ども向け

目的はダイエット管理ではなく食育である。

食品の特徴と自分の現在状態を理解し、「次に何を食べるか」を本人が考えられるようになることを目指す。

成功状態は、アプリへの依存ではなく、最終的にアプリなしでも食品の特徴や食事バランスをある程度判断できることである。

### 大人向け

目的は、現在手作業で行っているPFC記録を高速・省力化することである。

kcal / P / F / Cの実数値、日次合計、履歴などを直接扱う通常のPFCトラッカーとして設計する。

## 共通基盤

2アプリで共有可能な基盤として、以下を想定する。

- 食品マスタ / ユーザー食品DB
- JAN / GTIN等の商品識別子
- kcal / P / F / C等の栄養データ
- 食事ログの基本データ構造
- AIによる曖昧入力・自由入力・写真等の構造化
- 栄養計算ロジック
- 栄養値の出典・信頼度管理

栄養値は、商品ラベル・商品DB、ユーザー登録値、AI推定値など、由来を区別できることが望ましい。

## 設計上の分離原則

共通基盤を持つことと、同じUI・同じ評価思想を使うことは別である。

特に子ども向けへ、大人向けの減量・目標達成・超過警告の思想を持ち込まない。

巨大な共通基盤を先に完成させることを優先せず、まず子ども向けMVPで核となる学習体験が成立するかを検証する。

## 現在の優先順位

現在の最優先は子ども向けMVPである。

「食品を登録する → 食品のPFC特徴を見る → 今日の状態が動く → 次に食べるものを自分で考える」という最小ループを早く実機で試せる状態にする。
